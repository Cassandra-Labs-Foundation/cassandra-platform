## Reproduced defects

### BUG-01 · P1: Clearing a filing draft leaves values visible and allows them to be restored accidentally

**Steps:** Call Report → Financial Condition → enter `123.45` in AS0004 Coin and Currency → Tab to save → click `1 keyed · clear`.

**Actual:** the keyed count disappears, but AS0004 still displays `123.45`. Click that field and Tab out without editing; `1 keyed · clear` returns. The cleared value has been saved again. Switching to Income & Expense and back before clearing did preserve the value correctly, so this is specifically a clear/state synchronization defect.

**Expected:** clearing a draft clears every displayed field, derived count, and saved value. Focus/blur must not resurrect cleared data.

**Impact:** the form can display different values from its saved/export input state. A preparer can unknowingly restore discarded figures.

**Source:** `src/pages/call-report.jsx:510–518` uses uncontrolled `defaultValue` and writes on blur. `src/lib/useFormValues.js:60–63` clears state/storage without resetting mounted input DOM values. Use controlled inputs or an explicit synchronized reset mechanism, preserving editing behavior.

**Verification for a fix:** repeat the full sequence, reload, and verify the exported draft agrees with the cleared form. Export behavior was not exercised in this audit.

### BUG-02 · P1: A resource trace incorrectly says no gate decisions exist

**Steps:** Reports → Decision `block` → Apply → first RS-05 link → first event's `trace`. Then follow Recorded decisions in Reports and filter Subject to `instfrz_NCUA-FLOW-ORD-bfbb58fc`.

**Actual:** the trace for `institution_freeze:instfrz_NCUA-FLOW-ORD-bfbb58fc` loads five events but says “no gate decisions recorded for this resource.” Reports returns one RS-05 `block` decision, event `tr_77ad9d66-8d23-469b-90bc-1a213f178d31`, for that freeze ID. Reproduced twice.

**Expected:** the resource trace includes this decision or explicitly reports an association limitation, not a factual absence.

**Likely cause, supported by source:** `core/supabase/functions/api/dashboard.ts:529–547` uses the same exact resource string for event `resource_id` and decision `subject_ref`. In the observed rows, events use the type-prefixed string and the decision uses the bare ID. A fix needs canonical resource identity handling across writers/readers, not indiscriminate string stripping.

**Evidence:** [Trace omits decision](review-evidence-2026-11-09/trace-missing-decision.jpg), [Reports contains decision](review-evidence-2026-11-09/report-existing-decision.jpg).

### BUG-03 · P2: Narrow-screen Reports clips audit columns without a horizontal scrolling surface

**Steps:** open Reports filtered to RS-05; set viewport to 390 × 844; inspect the results table.

**Actual:** the table is approximately 540px wide inside a 263px container with computed `overflow-x: hidden`. Subject, Score, and Recorded are outside the visible region. The UI provides no table scrollbar to reach them.

**Expected:** the complete audit row remains accessible through horizontal scrolling or a responsive detail layout.

**Source:** `src/pages/reports.jsx:182` wraps the table in `overflow-hidden`. Introduce an appropriate scroll wrapper while preserving rounded borders and readable columns.

**Evidence:** [Clipped mobile report](review-evidence-2026-11-09/mobile-report-clipping.jpg).

### BUG-04 · P2: Compact sidebar links lose their accessible names

**Steps:** inspect the same page at 390px width.

**Actual:** all ten sidebar destinations appear as unnamed links in the browser accessibility snapshot. Icons remain visible, but their text labels are hidden and there is no alternative accessible name.

**Expected:** links retain names such as Home, Teller, and Reports at every breakpoint, even if visual labels collapse.

**Source:** `src/components/layout/MainLayout.jsx:332–345`: the link has no `aria-label`; its only textual name has `hidden md:block`. Keep a screen-reader label or apply an explicit link name. Also add `aria-current` for the active destination.

### BUG-05 · P2: Cleared report filters return on reload because the URL remains stale

**Steps:** follow a control's Recorded decisions in Reports link, arriving at `/reports?control_id=RS-05` → Clear → reload.

**Actual:** Clear empties the control input and requests unfiltered results, but the URL still contains `control_id=RS-05`. Reload restores RS-05 and filters the report again. Manually applied decision/subject filters likewise do not update the URL.

**Expected:** the address represents the applied report state. Clearing removes the query parameters; reloading or sharing preserves what the user was viewing.

**Source:** `src/pages/reports.jsx:76–89` initializes from query parameters; `:155–160` clears only component state. Synchronize applied filters with the router and support each filter consistently.

### BUG-06 · P2: Accounting drilldown cannot be dismissed with Escape and has an unnamed close control

**Steps:** Accounting → Total shares & deposits → press Escape.

**Actual:** the All share accounts overlay remains open. Its close button has no accessible name. It does close when clicked. The overlay is built from generic containers; no dialog role or focus behavior is declared in the component.

**Expected:** a named dialog/panel with a named Close button, Escape dismissal, predictable focus entry and return, and keyboard-accessible triggers.

**Source:** `src/pages/accounting.jsx:339–347`; clickable summary/line elements elsewhere in the file also use nonsemantic elements. Escape failure and unnamed close button were observed live; a complete focus-trap traversal was not performed.

**Evidence:** [Panel remaining open](review-evidence-2026-11-09/accounting-panel.jpg).

### BUG-07 · P2: Global search keeps selectable results after the query changes

**Steps:** in Teller, expand the first recent transfer, copy its ID `tr_18162f83-bf96-427d-b3d6-3c7f5b20b9bf` into global search, and press Enter. After Elena Marsh appears, replace the query with `Caleb` without pressing Enter.

**Actual:** the dropdown still offers Elena Marsh under the edited query. There is no indication that those results belong to the previous search.

**Expected:** invalidate or hide results on input change, or label them with the submitted query and require a new search before presenting them as matches.

**Source:** `src/components/layout/MainLayout.jsx:77` only changes `term`; result rendering at `:90–103` is independent of the current query. Existing request sequence protection only advances when a search is submitted, not when the query changes or closes.

### BUG-08 · P3: Member/account detail return navigation loses the originating workspace

**Steps:** Member Services → Caleb Fry → Full profile → account → Back to Teller.

**Actual:** both detail pages offer a hardcoded Teller return link even when opened from Member Services. Following it lands in Teller, discarding the member-services selection and search context.

**Expected:** preserve a meaningful return destination and context, with a safe fallback for directly opened links. A specifically labeled Teller shortcut can remain separately.

**Source:** `src/pages/accounts/[id].jsx` and `src/pages/members/[id].jsx`, hardcoded `/teller` links. This is a workflow defect, not a broken URL.

## Additional concerns, separate from the reproduced defect count

- **Accounting mixes scopes in one statement.** Observed assets/FBO of $95,534,912 and all-program deposits of $96,645,912, a $1,111,000 difference. The position drilldown and statement footer explicitly explain this scope difference, so it is not an unexplained reconciliation failure. Still, comparing these as Total assets and Total liabilities & equity makes the statement difficult to interpret. Present a single consistent scope or clearly separate the scopes before the totals. Source: `src/pages/accounting.jsx:524–541`. [Evidence](review-evidence-2026-11-09/accounting-scope.jpg).
- **Noncurrency filing fields use the currency input path.** AS0010 asks for yes/no, but renders the shared decimal-oriented input. Typing `yes` was accepted visually and then removed during cleanup. Source routes PDF values through `keyedCents`, suggesting the answer may disappear in output. PDF output was not checked, so export loss remains a follow-up hypothesis, not a confirmed bug.
- **App-wide live provenance remains unclear.** The prior critique's unlabeled local teller drawer and seeded persona findings still apply. No cash actions were submitted in this pass.
